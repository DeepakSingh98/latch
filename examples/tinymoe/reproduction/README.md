# TinyMoE learning experiment reproduction

This is the full small-batch experiment configuration, separate from the
[short software quickstart](../README.md). It compares learning procedures with
different batch sizes. It does not measure a same-batch execution speedup.
The included data manifests pin the reproduction inputs. Historical results
do not numerically qualify a newly compiled runtime.

`PLAN.md` defines the 131,072,000-token pilot. The historical `CONFIRMATION.md`
and `confirmation.json` describe a separate **1,048,576,000-token longer-horizon
study**, with three fresh seeds and eight frozen targets. Its changed learning-rate
schedule prevents interpreting it as direct pilot replication. Five-percent
warmup is 6,553,600 tokens in the pilot and 52,428,800 tokens in the longer study;
cosine decay also depends on the horizon. Early longer-study targets therefore
do not replicate the pilot schedule.

`FOLLOWUP.md` and `followup.json` separately freeze direct original-schedule
replication and schedule isolation, without retuning. Report every frozen target
and every seed, including unreached targets. Do not use automatic target selection
for either follow-up. See the [release limitations](../../../docs/NOTES.md)
before interpreting a new run.

## Data and initialization

The experiment uses the public TinyMoE architecture and tokenizer at revision
`9b209f7439aadfac282e0bf44f2fda19771aba90`, with random weights generated by
Transformers 4.55.4. Training examples contain 1025 tokens within one document:
1024 input positions and 1024 supplied next-token targets. The FineWeb-Edu
selection's document-level train/validation/test splits are preserved.

Exact historical data preparation uses the included selection metadata
`corpus.json`, `selected-rows.bin.gz` and `selection.json`. The first is pinned to SHA256
`75e67515b176d59a594c4727b0e0e8f7131427d22bec3c56fcd4d3949dba8590`; it binds the
original document index and all public Hugging Face shard URLs and hashes. The
2.1 MB compact index retains all 531,810 selected document coordinates and split
labels from the hash-verified original index; it contains no document text.
`selection.json` binds that derivation to both source hashes. The public helper
downloads the pinned public shards with full-file hash verification, then reads
these exact rows. It has no cloud-account dependency. The original JSONL index
is also accepted through `--documents` when available.

`corpus-windows.json` records the historical token-array and coordinate hashes.
Compare each generated split's `sha256`, `coordinates_sha256` and `windows` with
that file after preparation. The overall generated manifest hash also includes
preparation timing and public provenance changes, so it need not equal the
historical manifest hash. A new subset is not an exact reproduction of the result.

On CPU workers with the release installed:

```sh
python -m megakernel_lab.tinymoe data download --model-dir model
python -m megakernel_lab.tinymoe.learning corpus --model-dir model \
  --source-manifest examples/tinymoe/reproduction/corpus.json \
  --selection-index examples/tinymoe/reproduction/selected-rows.bin.gz \
  --selection-receipt examples/tinymoe/reproduction/selection.json \
  --out fineweb-windows --scratch corpus-scratch --workers 8
python -m megakernel_lab.tinymoe.learning init-state \
  --model-dir model --seed 1730 --out init-1730
python -m megakernel_lab.tinymoe.learning build --model model \
  --out b2-artifact --cache-dir build-cache --batch-size 2 --device-unit-jobs 8
```

Repeat initialization for seeds 1731 and 1732. Both arms of each pair must load
the exact same initial-state file and use that seed as their data-order seed.
Compilation uses 16 separate device units behind one cooperative kernel entry.
The staged optimizer is a normal captured `tensor_update` supplied through
`tinymoe.build.prepare(..., optimizer_factory=...)`; there is no global monkeypatch.

## Direct original-schedule replication

The frozen follow-up uses the same selected peak rates, data and paired initial
weights with `--horizon-tokens 131072000`, the pilot's 4,194,304-token evaluation
cadence, and seeds 1730/1731/1732. Run both arms sequentially on the same otherwise
idle H100 for each seed. For seed 1730:

```sh
python -m megakernel_lab.tinymoe.learning train --arm A \
  --model-dir model --data-dir fineweb-windows --init init-1730/init-s1730.pt \
  --out short-a-1730 --learning-rate 2.4e-3 --horizon-tokens 131072000 \
  --stop-tokens 131072000 --order-seed 1730 --eval-every-tokens 4194304 \
  --eval-windows 256 --final-eval-windows 2048 \
  --checkpoint-every-tokens 67108864 --save-final
python -m megakernel_lab.tinymoe.learning train --arm B2 \
  --model-dir model --data-dir fineweb-windows --init init-1730/init-s1730.pt \
  --artifact b2-artifact --out short-b2-1730 --learning-rate 3e-4 \
  --horizon-tokens 131072000 --stop-tokens 131072000 --order-seed 1730 \
  --eval-every-tokens 4194304 --eval-windows 256 --final-eval-windows 2048 \
  --checkpoint-every-tokens 67108864 --save-final
```

Repeat for seeds 1731 and 1732, keeping the same initial-state file and data-order
seed within each pair. The separate schedule-isolation pair uses seed 1729,
`--horizon-tokens 1048576000 --stop-tokens 131072000`, and the same 4,194,304-token
evaluation cadence; compare with the existing seed-1729 pilot results. Changing
only `--stop-tokens` does not rescale warmup or cosine decay.

The direct-replication targets are the frozen pilot levels **4.612, 4.466, 4.34,
4.254, 4.187, 4.141, 4.116, 4.107**. Also report all longer-study targets below
where reached, every seed, matched-token dev NLL, accumulated update time and
the separate final 2048-window evaluation. The packaged historical `learning
confirm` reducer accepts only the longer-study horizon and cadence; it cannot
certify these follow-up runs. Preserve all per-run receipts and validate the
follow-up identities and complete frozen target table against `followup.json`.
No automatic direct-replication reducer is included in this frozen runtime.

## Longer-horizon study: preserved frozen commands

On otherwise idle single-H100 workers, for each seed:

```sh
python -m megakernel_lab.tinymoe.learning train --arm A \
  --model-dir model --data-dir fineweb-windows --init init-1730/init-s1730.pt \
  --out a-1730 --learning-rate 2.4e-3 --horizon-tokens 1048576000 \
  --order-seed 1730 --eval-every-tokens 8388608 --eval-windows 256 \
  --final-eval-windows 2048 --checkpoint-every-tokens 67108864 --save-final
python -m megakernel_lab.tinymoe.learning train --arm B2 \
  --model-dir model --data-dir fineweb-windows --init init-1730/init-s1730.pt \
  --artifact b2-artifact --out b2-1730 --learning-rate 3e-4 \
  --horizon-tokens 1048576000 --order-seed 1730 \
  --eval-every-tokens 8388608 --eval-windows 256 --final-eval-windows 2048 \
  --checkpoint-every-tokens 67108864 --save-final
```

For restart, pass `--resume previous-run/checkpoint.pt` and a new output directory
with the same remaining arguments. Use only checkpoints created by your trusted
run. Exact continuation requires the bound corpus/order/initial weights,
hyperparameters, optimizer, artifact, library and runtime identity; copying a
cache to another directory does not establish compatibility.

After all runs complete, evaluate each saved parameter file once on test:

```sh
python -m megakernel_lab.tinymoe.learning evaluate-final \
  --model-dir model --data-dir fineweb-windows --split test --windows 4096 \
  --run A1730=a-1730/final-parameters.pt --run B21730=b2-1730/final-parameters.pt \
  --out test-1730
python -m megakernel_lab.tinymoe.learning confirm \
  --run A:1730=a-1730 --run B2:1730=b2-1730 \
  --run A:1731=a-1731 --run B2:1731=b2-1731 \
  --run A:1732=a-1732 --run B2:1732=b2-1732 --out confirmation-results.json
```

The historical `learning confirm` reducer verifies the longer-study seed, rate, horizon and evaluation settings,
compares pair identities, retains all target crossings and reports missing runs.
Target crossings use the first observed evaluation at or below the threshold and
the preceding evaluation as a lower resolution bound; there is no interpolation.
Its result is a longer-study summary, not a certificate of pilot replication.

## Short machinery check

Prepare a separate small public corpus to exercise this software without the
full FineWeb-Edu selection. This check needs 262,144 training targets; the
ordinary quickstart's 65,537-token corpus is too short. Run preparation and
initialization on CPU, then training on the H100 with the B2×S1024 artifact built
above:

```sh
python -m megakernel_lab.tinymoe data prepare --model-dir model \
  --out smoke-data --train-tokens 262145 --eval-tokens 8193
python -m megakernel_lab.tinymoe.learning quick-windows --source smoke-data --out smoke-windows
python -m megakernel_lab.tinymoe.learning init-state --model-dir model --seed 1729 --out init-smoke
python -m megakernel_lab.tinymoe.learning train --arm B2 \
  --model-dir model --data-dir smoke-windows --init init-smoke/init-s1729.pt \
  --artifact b2-artifact --out smoke-run --learning-rate 3e-4 \
  --horizon-tokens 1310720 --stop-tokens 262144 --order-seed 1729 \
  --eval-every-tokens 131072 --eval-windows 8 --final-eval-windows 8 \
  --checkpoint-every-tokens 131072 --save-final
```

These packed-stream smoke windows may cross source rows and are explicitly
different from the historical learning corpus. They support software validation,
not the reported learning claim. The optional `build-ga` command exposes the
published-configuration accumulating tensor rule; its router reduction differs
from the full learning protocol and must not be substituted into these runs.
