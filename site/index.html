A compiler for training megakernels

Suppose you’ve got an idea for a new learning algorithm.

The further it strays from familiar methods, the more of its implementation you’ll have to build yourself. Conventional methods have earned their place, and an entire ecosystem of kernels, libraries, and compilers has co-evolved with them through a decade of optimization. If your idea is radical enough, you have a systems project to finish before you can test it, let alone iterate on it.

Systems work holding research back, then enabling it, is nothing new:

  • AlexNet relied on an efficient GPU implementation to make training practical.
  • The Transformer removed recurrence and made sequence training much more parallel.
  • FlashAttention made longer contexts practical by reducing how much data attention moves through GPU memory.

One exciting new primitive is the megakernel: fusing long sequences of GPU operations into a single kernel. This can reduce launch overhead and memory traffic while keeping the GPU busy between operations.

Hazy Research demonstrated this approach for whole-model inference. Cursor’s Mixture-of-Kittens applied it to mixture-of-experts training. Flapping Airplanes is pursuing megakernels as a route to more data-efficient learning, with early results earning them a $1B Series A.

Like most people reading this, I don’t have a billion dollars in venture funding. I’m also lazy. A training megakernel has to fit the forward pass, backward pass and optimizer into one program, and every change to the model means reworking it. In order to explore radically different ideas without rewriting a kernel each time, I built Latch.

Latch is a compiler for training megakernels on H100s. Give it supported PyTorch training code and it generates one GPU program for the forward pass, loss, backward pass and optimizer update, handling the dependencies, memory reuse, and synchronization between them. When your experiment changes, you regenerate the kernel instead of rewriting it.

Latch trained TinyMoE-200M to the same validation loss with 40% less training-update time than compiled PyTorch. Small-batch updates ran 2.75× faster.

What I’m most interested in are learning procedures that are impractical with today’s tools. In GradLev, a model updates its weights as it reads, one token at a time. Latch runs all 1,024 adaptation steps for GPT-2 small’s final MLP in a single kernel, keeping the changing weights in shared memory throughout. The complete block ran 3.5× faster than compiled PyTorch replaying a CUDA graph; both use ordinary PyTorch for the rest of GPT-2. The GradLev example is included in this release.

This release includes runnable TinyMoE training, selective weight updates, repeated layers, GradLev token-by-token adaptation and smaller fast examples. Earlier compiler work also explored state-space, diffusion and energy-based models; see the included examples.

Latch is a research preview and a first step toward an open-source megakernel framework that enables weird new ways to learn. The source archive, wheel and instructions are available together. The open problems are a good place to start, and I’m curious to see what people explore with it.
