Results

Latch generates GPU programs from models and learning rules. We test how fast they run and how much the compiler can handle.

Faster execution

These clocks compare complete updates of the same model and learning recipe. Each run uses one H100; the paired measurements were repeated on two H100s at fresh, mid and late training states.

The fastest conventional control measured here compiles the trunk with TorchInductor and replays a CUDA graph. Its recipe-Q numerical limitation is described below. These are execution ratios, not data-efficiency gains.

Training to the same quality

TinyMoE-200M trains from random initialization on the same fixed text stream. Each comparison below keeps the recipe and batch size fixed between Latch and the conventional control. The target is validation loss 3.30. The full horizon is 655.36 million tokens.

The confirmation used the same generated program as this release. Its batch-2 full training results remain from the earlier compiler.

Update time excludes compilation, evaluation and checkpointing. In the Q confirmation, elapsed time from the first evaluation panel to the target panel, including evaluation and checkpoints, was 1,117 versus 1,766 seconds.

Numerical scope. Latch passes the tested fresh- and trained-state FP64 checks. The conventional control fails one trained-state gradient check: relative L2 error 0.0914 against a 0.08 limit, traced to TorchInductor rounding placement. It remains the fastest measured control, but is not numerically qualified.

Batch size changes the learning recipe. In the earlier full runs, tuned B2 needed fewer tokens than B32 to reach the target, but about 2.8× as much update time.

Different models and learning rules

The compiler determines operation order, synchronization and memory reuse from the input program. This release includes TinyMoE, selective updates, looped SMELT-style TinyMoE, GradLev and the fast-example families. Examples and installation.

E2-TTT, Granite and experimental distributed training remain research workloads outside this runnable release.

Latch is a research preview with a limited set of supported operations. The goal is to make changing a learning program enough to produce a new GPU implementation. How the compiler works.
